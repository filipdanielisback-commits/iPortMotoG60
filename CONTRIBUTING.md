# Contributing

Contributions are welcome for careful, well-sourced research and documentation.

## Before submitting

- Explain which exact device variant, board, and firmware your information applies to.
- Include source links for technical claims.
- Separate direct observations from assumptions.
- State whether a result is independently reproducible.
- Respect the license of every source file and dependency.

## Evidence labels

Use one of these labels in research notes:

- **Verified** — confirmed by a reliable primary source or reproducible test.
- **Reported** — stated by a source or contributor but not independently confirmed.
- **Inferred** — a reasoned interpretation, not a confirmed fact.
- **Unknown** — not yet established.

## Do not contribute

- Proprietary Apple binaries, firmware, private keys, certificates, or signing material.
- Leaked or unlawfully obtained source code.
- Files copied from another project without checking its license.
- Claims that iOS 26 boots unless supported by clear, reproducible evidence.
- Instructions encouraging risky device modification without a verified recovery plan.

## Research note template

```text
Topic:
Device variant:
Firmware/build:
Claim:
Evidence label:
Source URL(s):
What the source establishes:
What remains unknown:
Reproduction notes:
License/usage notes:
```

## Pull requests

Keep changes focused. Update the relevant compatibility or hardware-support document when new evidence changes the project's assessment.
